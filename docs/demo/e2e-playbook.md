# 演示脚本（5 分钟版）· v1.0

> 归属：M3（同学 C）· 2026-10-29
> 用途：初赛材料的连续演示录屏、决赛现场 5 分钟展示、内部彩排，共用这一套步骤。
> 原则：**每一步都是真实操作，录屏不剪辑**。计划 §1 明确「评测可随机测试，不能靠静态截图替代真实执行」。

---

## 0. 演示前 3 分钟检查（必做，避免现场翻车）

| 检查项 | 命令 / 动作 | 通过标准 |
|---|---|---|
| 数据装载 | 用测试账号导入 `fixtures/education/` 三条场景 | 今天/明天能看到对应课程与任务 |
| Agent 链接 | 换一个非开发账号打开 | 能打开且能触发工具（不是纯聊天） |
| 工具连通 | 让它查一次明天任务 | 返回内容与 CheckD 内一致 |
| 网络 | 检查工具调用耗时 | 单次 < 5 秒 |
| 录屏软件 | 分辨率 1920×1080，声音正常 | 试录 10 秒回放 |

任何一项红 → 改用兜底剧本（见第 6 节），不要硬演。

## 1. 开场（30 秒）

**说什么：**
> "我是 CheckD 组的 C。CheckD 是一个给大学生用的任务打卡与时间记录 App，已经有课程表、周期任务、计时、复盘这些真实功能。
> 我们这次做的不是给 App 加一个聊天框，而是让腾讯 WorkBuddy 上的智能体能**真正读写** CheckD 的数据——读你的课表和待办，帮你排出无冲突的计划，你点头之后它才写回，写完还要回读核对。
> 接下来三分钟，我用同一份测试数据跑三个场景，每一步都是真的。"

**画面：** CheckD 今日页 → 切到 WorkBuddy Agent 对话页。

## 2. 场景一：学习计划（60 秒）

**输入（照读，不要改词）：**
> 帮我看看明天有哪些课和要做的事，然后把英语单词复习安排到有空的时间里。

**预期看到：**
1. Agent 调用 `list_tasks` 与 `get_calendar_events`（有真实返回，不是"我猜你有课"）。
2. 列出明天的：数据结构 14:00-15:40、学生会例会 19:00-20:00、高数习题已排 20:30-22:00。
3. 给出提案：英语复习 20:00-20:25，并说明"例会结束后有 30 分钟空档"。
4. 显示「计划前/后」差异（对照 `before-after-spec.md`）。

**说什么（点睛）：**
> "注意它没有把英语复习塞到 14 点的课上，也没有动已经排好的高数习题——这两个约束在数据层是硬的。"
> "现在还是待确认状态，我故意不点确认，先让它读一次数据库。（截图）确实是空的，没写。"

**必截图：** ①工具调用日志 ②前后差异卡片 ③确认前的数据库空状态

## 3. 场景二：复杂任务拆解（60 秒）

**输入：**
> 我三天内要交一份科研报告，现在完全没头绪，帮我拆成能直接动手的子任务，再按我的空闲时间排一排。

**预期看到：**
1. 拆出 ≥4 个子任务（文献综述 90 / 数据清洗 45 / 结果分析 75 / 图表 60 / 正文 90），合计 360 分钟。
2. 只排进晚上 20:00-22:00 的学习窗口，组会那晚少 60 分钟。
3. **明确说出"还有 60 分钟排不下"**，并给建议。

**说什么（点睛）：**
> "这里最容易翻车：大部分 Demo 会把 360 分钟的活硬塞进 300 分钟里，看起来排满了，实际上不可能完成。
> 我们的处理是——排得下的排，排不下的明说。这条是本项目的诚实性红线。"

**必截图：** ④子任务列表与时长合计 ⑤未安排 60 分钟的提示

## 4. 场景三：突发事件重排（60 秒）

**输入：**
> 下午三点到四点半临时有个会，帮我把今天的安排重排一下，其他尽量别动。

**预期看到：**
1. 识别出只有「高数习题 15:00-16:00」与会议重叠。
2. 只移动这 1 个块，其余 3 个块位置不变。
3. 给出移动理由（例如挪到 16:40-17:40，仍在今日截止前）。
4. 点击批准 → 写入 → **回读**显示日历确实变了。

**说什么（点睛）：**
> "这是我们的核心创新点：不是重新排一遍，而是最小扰动重排——固定课程一次都没动，只挪该挪的那一个。"

**必截图：** ⑥重排前后对比（1 动 3 不动）⑦批准后真实日历回读

## 5. 收尾（30 秒）

**说什么：**
> "三条场景都用同一份脱敏测试数据，可以随时复现。代码在 GitHub，接口契约、测试用例、差异展示规格都在 docs 里。
> 我们没有伪造任何一步执行结果——排不下的就报排不下，失败的就说失败。这是我们认为教育类智能体该有的样子。"

## 6. 兜底剧本（现场故障时按序降级）

| 故障 | 降级动作 | 怎么说 |
|---|---|---|
| Agent 链接打不开 | 切本地录好的连续录屏（不剪辑） | "现场网络问题，这是 10 分钟前同一份数据的完整录屏" |
| 工具超时 | 截取错误提示 + 说明设计上的失败处理 | "它没有编造数据，而是明确报错——这正是 E11 用例" |
| 写入失败 | 展示失败 → 重试 → 成功全流程 | "失败可见、可重试，比假装成功更有价值" |
| 数据被改动 | 用备份 seed 恢复后重跑 | "测试数据是脚本装进去的，30 秒可复位" |

**禁止：** 用截图假装实时操作；说"这个功能其实是好的只是现在跑不了"。

## 7. 决赛 5 分钟与答辩 5 分钟的分工建议

| 时间 | 内容 | 主讲 |
|---|---|---|
| 0:00-0:40 | 问题与定位（大学生计划失效的真实痛点） | C |
| 0:40-1:40 | 场景一：读+排 | C |
| 1:40-2:40 | 场景二：拆解与诚实性 | C |
| 2:40-3:40 | 场景三：最小扰动重排 | C |
| 3:40-4:20 | 架构一页图（WorkBuddy → 适配层 → CheckD） | M0 |
| 4:20-5:00 | 工程严谨性（契约、13 条边界、可复现） | C |

**答辩预判问题（C 准备）：**
1. "这和直接在 App 里做计划有什么区别？" → 关键在自然语言入口 + 跨系统真实写入 + 审批可回滚。
2. "排不下怎么办？" → 明说缺口，不静默丢弃（E02/E07）。
3. "怎么保证不动我的课？" → 课程在数据层是 hard 约束，提案层校验，写入前二次校验（E06/E12）。
4. "重复点确认会不会排两遍？" → overrideId 复用，天然幂等（E08）。
5. "链接别人能打开吗？" → 已用非开发账号验证，记录时间与账号类型（E10）。
