# 匿名与隐私 / 密钥检查清单

> 主笔：M3（同学 C）· 2026-10-29，当晚按方案原件补充红线条款
> 依据：方案原件附件一「核心要求」**原文**：「PPT 文档、答辩视频及所有提交材料中，**严禁**出现参赛学生姓名、学号、指导教师等任何身份信息，**违者直接取消评奖资格**。」
> 使用时机：**每次提交材料前**、**每次录屏后**、**每次 PR 合并前**。三项都不做，等于把风险留给评委发现。

> ⛔ **这不是扣分项，是一票否决项。** 前面所有分数加起来 100 分，匿名违规一次全部作废。所以本清单的优先级高于任何功能开发与文档美化——**宁可少交一份材料，不可留一处身份信息**。

## 1. 身份匿名（材料层）

| # | 检查项 | 怎么查 | 通过标准 |
|---|---|---|---|
| 1.1 | 成员真实姓名 | 全文搜索材料（md/docx/pdf/pptx） | 0 处 |
| 1.2 | 指导教师姓名 | 同上 | 0 处 |
| 1.3 | 学校/学院名称、校徽 | 看封面、页眉页脚、PPT 母版 | 0 处 |
| 1.4 | 学号、班级 | 同上 | 0 处 |
| 1.5 | 个人联系方式（手机、微信、邮箱） | 同上 | 0 处 |
| 1.6 | 截图中的账号信息 | 放大看 WorkBuddy/GitHub/Supabase 界面右上角 | 已打码或裁掉 |
| 1.7 | 文件名/路径暴露姓名 | 看目录树，如 `C:\Users\张三\...` | 已裁掉或在无路径环境重拍 |
| 1.8 | 文档属性（作者/最后修改者） | docx/pdf/pptx 属性面板 | 已清空或改为中性名 |
| 1.9 | **录屏画面里的桌面/任务栏/窗口标题** | 逐帧抽查录屏开头与切换窗口处 | 无 `C:\Users\姓名\`、无本人姓名文件夹 |
| 1.10 | **邮件发件人昵称与签名** | 发出前看一眼发件人显示名 | 为中性名，非真实姓名 |
| 1.11 | PPT 母版/页脚/备注页 | 视图 → 幻灯片母版、备注页 | 无学校名、无姓名 |

**C 已做的部分：** `fixtures/education/` 全量通过自动 PII 扫描（手机号/身份证/邮箱/学号四类正则），用例中的学生统一称「学生A」「学生B」。

复查命令：

```bash
python fixtures/education/validate_fixtures.py --privacy
```

## 2. 密钥与凭据（代码层）

| # | 检查项 | 怎么查 | 通过标准 |
|---|---|---|---|
| 2.1 | `SUPABASE_KEY` / `SERVICE_ROLE_KEY` | 搜仓库全文 `service_role`、`SUPABASE_`、`anon` | 仓库内 0 处真实值 |
| 2.2 | `Authorization` / `Bearer` | 搜 `Bearer ` | 只出现在示例占位符 |
| 2.3 | `.env` 类文件 | 查 `git ls-files` 是否含 `.env` | 未跟踪，且有 `.gitignore` |
| 2.4 | 工具 token / MCP 配置 | 看截图与文档代码块 | 已替换为 `<token>` |
| 2.5 | 数据库连接串 | 搜 `postgres://`、`postgresql://` | 0 处真实串 |
| 2.6 | Git 历史里泄露过 | `git log -p -S "service_role"` | 无命中，或已确认仅为占位 |

**M0 负责执行 2.x**（C 只做复核）。若在历史提交里发现真实密钥：不是删文件就算完，必须**轮换密钥**并在 `OSS_DISCLOSURE.md` 记录处置过程。

## 3. 个人数据脱敏（数据层）

| # | 检查项 | 通过标准 |
|---|---|---|
| 3.1 | 课表数据 | 用通用课名（高等数学/大学英语/数据结构），不出现真实院校课程代码 |
| 3.2 | 教室/教师 | 用「教学楼A301」「张老师」这类占位，非真实姓名 |
| 3.3 | 任务内容 | 不出现真实论文题目、真实公司名、真实项目代号 |
| 3.4 | 聊天/知识库截图 | 无真实同学姓名、群名、头像 |
| 3.5 | 邀请链接/分享码 | 截图前确认不含可被他人利用的分享码 |
| 3.6 | 时间戳 | 可保留（不影响匿名），但不要暴露"深夜还在改"之类的隐私画像 |

**判断标准：** 把材料给一个陌生同学看，他能推断出"这是哪个学校哪个人的数据"吗？能，就是没脱敏。

## 4. 证据真实性（这条最容易被忽视，但直接影响可信度）

| # | 检查项 | 通过标准 |
|---|---|---|
| 4.1 | 截图是否来自真实运行 | 有对应的工具调用日志/时间戳；不是 PS 或手拼 |
| 4.2 | 是否有"未执行却显示成功" | 0 处。失败必须显示失败 |
| 4.3 | 录屏是否剪辑掩盖失败 | 连续录制，失败片段保留 |
| 4.4 | 排不下时是否明说 | 有 `unplanned_tasks` 提示（对应 E02/E07） |
| 4.5 | 数据是否可复现 | 评委按 `docs/demo/e2e-playbook.md` 能重跑出同样结果 |

## 5. 提交前 10 分钟终检（照做）

1. 对每个文件跑一遍匿名搜索（姓名、学校、学号、手机、邮箱）。
2. 打开 docx/pdf/pptx 属性，清空作者与公司。
3. 抽查 3 张截图，放大看账号区域。
4. `git ls-files | grep -i env` 确认为空。
5. 在无痕浏览器、非开发者账号打开 Agent 链接，截图留存。
6. 让一个不参与项目的同学按演示脚本走一遍，记录他卡在哪。
