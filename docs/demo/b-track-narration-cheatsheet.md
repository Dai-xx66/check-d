# B 轨录制 · 提词速查（术语读音 + M0 口语版）

> 用途：录屏时放第二屏。左列是屏幕上会出现的词，中列是**你可以直接这么说**，右列一句话含义。
> 原则：技术词可以口语化，**判据值必须照念**（违规码、状态值、错误码），念错会被当成事实错误。

## 1. 技术词怎么念

### 1.1 工具名（7 个，屏幕左上 `-> tools/call <名>` 出现）

| 屏幕上的 | 你就念 | 一句话含义 |
|---|---|---|
| `list_tasks` | 列任务 | 读任务清单（只读） |
| `get_calendar_events` | 取日历事件 | 读课表与固定会议（只读） |
| `generate_schedule` | 生成日程 | 排时间，产出**提案**，不写入 |
| `validate_schedule` | 校验日程 | 检查冲突、越界，返回违规清单 |
| `request_approval` | 请求审批 | 把「将改什么」摊开给用户确认 |
| `get_approval_status` | 查审批状态 | 问用户批了没有、有没有 Token |
| `apply_approved_changes` | 应用变更 | 真正写入的那一步（本轨为 Mock） |

### 1.3 状态值与代码（**必须照念，别翻译**）

| 值 | 含义（不必念，只是让你知道在说什么） |
|---|---|
| `draft` | 提案刚生成，未提交 |
| `pending` | 等用户确认 |
| `approved` | 用户已确认 |
| `applying` | 正在写入，没结束 |
| `readback_pending` | 写完但没回读，未终局 |
| `applied` / `failed` | 已生效 / 失败 |
| `READBACK_PENDING` | 回读待定（错误码，503） |
| `READBACK_MISMATCH` | 回读不一致（错误码，502） |
| `IDEMPOTENCY_IN_PROGRESS` | 同一请求正在处理中，拒绝重复写（409） |
| `BLOCK_OVERLAP` | 两个时间块重叠（本次新增的第 8 个违规码） |
| `FIXED_EVENT_CONFLICT` | 与固定课程/会议冲突 |
| `APPROVAL_REJECTED` | 审批被拒 |

### 1.4 几个技术名词

| 词 | 你就念 |
|---|---|

## 2. M0 的口语版八条 ↔ 你的镜次 ↔ 一句人话

M0 原话是「像给老师/评委展示产品一样，实际操作一次」，他给的八条用大白话就是下面这些。你不用背他的话，用第三列这句人话讲就行。

| M0 口语八条 | 你的镜次 | 你开口这么说（人话版） |
|---|---|---|
| 1 片头 ≥3 秒「MOCK · 非真实写入」，全程角标 | 镜 0 + 镜 1 | 「这段是模拟环境演示，不写真实数据库；先看工具都连上了，7 个。」 |
| 2 用户提需求（一句自然语言） | 镜 2 / 镜 3 口播 | 「我的需求是：把这周的报告拆成子任务，连固定课一起排进日程。」 |
| 3 Agent 读取信息 | 镜 2 | 「它先去读我的任务和课表，这是真读出来的，每条都有请求 ID。」 |
| 4 任务拆解成结构化结果 | 镜 3 | 「一句需求变成了结构化提案：几条变更、几个时间块、哪些排不下。」 |
| 5 日程生成 + 冲突/未安排校验 | 镜 3 + 镜 4 | 「时间排出来了，再看校验：有没有冲突、有没有硬塞。」 |
| 6 方案预览 + 模拟审批 | 镜 5 + 5a | 「改什么摊开给我看，我不点确认，就一个字节都不动；这只是模拟审批。」 |
| 7 异常/恢复边界 | 镜 6 + 镜 7 | 「写入这一步它停在了未终局状态，同键重试还是被拦；这条路径没收敛，我不说它收敛了。」 |
| 8 结果收尾 | 镜 8 + `fin` | 「重复点、换键、执行中重试，三道闸都拦住了；真实写入和真实审批仍 BLOCKED。」 |

## 3. 禁语（出口即违规，事后无法补救）

- ❌ 写入成功 / 已经写进数据库 / 数据已更新
- ❌ 真实审批、真实 Token 已验证
- ❌ 回读一致、闭环完成
- ❌ 崩溃路径已恢复 / 已收敛
- ❌ A 轨已完成、可以上线
- ❌ 端到端生产验证

## 4. 卡住了怎么办

念不下去就停两秒，指一下屏幕说「这里是刚才那个返回」，然后继续。**不要停录制、不要重开驱动**——一次连续录制是硬要求。
