## 8 镜执行卡

| 镜 | 你做什么 | 画面必须出现 | 口播关键句 |
|---|---|---|---|
| 1（20s） | 片头 3 秒 → 展示工具已加载 | 片头 `MOCK · 非真实写入`；`7/7 tools loaded` | "教育场景：一周学习计划，含固定课程与临时会议。" |
| 2（30s） | 发"看看我下周的任务和课表" | `list_tasks` + `get_calendar_events` 两次调用、`request_id` 可见 | "这两个是只读调用，不是提示词编的。" |
| 3（50s） | 发"把课程报告拆成子任务，这周做完" | Proposal 卡：`proposal_id`、`status=draft`、`changes[]` 分色、`explanations[]`、`expires_at` | "这是**提案**，不是写入；排不下的进 `unplanned_tasks` 并给 `reason_code`。" |
| 4（40s） | 点"校验计划" | `valid=true` 或 `violations[]`（对象 + 七值闭集） | "冲突要说清**哪一条**违规、**为什么**。" |
| 5（40s） | 点"请求审批"→ 展示面板 →（建议）点一次取消 | `approval_readiness`（不是 `approval_status`）；点确认后才出现打码 Token；取消后回读无变化 | "用户不点确认，数据库一个字节都不变。" |
| 6（40s） | 点"应用变更"（带 `Idempotency-Key`） | `READBACK_PENDING` 503、`retryable=true`、`details` 含 `proposal_status=applying` 与 `business_write_count_delta=0` | "写入次数只有一次；重复点、换键、执行中重试，都拿到零写入的确定性错误。" + "**这是 Mock 按契约给出的断言，不代表真实端点已验证。**" |
| 7（40s） | 再调 `list_tasks` 回读 | 回读前后对比；固定课程未移动 | "回读一致才叫成功。" + "崩溃路径停在 `applying`、同键只回 `IDEMPOTENCY_IN_PROGRESS`，**这条路径没有收敛**，不说成已收敛。" |
| 8（30s） | 同键重试一次 → 再换新键一次 | 同键 `IDEMPOTENCY_IN_PROGRESS`（409）；新键 `READBACK_PENDING` 且 delta=0 | "这就是防重复写入的三道闸。" |

**收尾声明（必须说）**："以上全部为 Mock 环境流程演示；真实写入、真实审批、生产回读仍为 **BLOCKED**，待 A 轨补录。"

## 录完立刻自检（8 条，缺一条重录）

1. 片头 `MOCK · 非真实写入` 是否**停满 ≥3 秒**？
2. 8 镜全程右下角角标是否**一直在**（无被裁切、无被窗口遮挡）？
3. 是否说过"当前是 Mock 后端、不是真实业务端点"（至少片头 + 收尾各一次）？
4. 有没有任何一句把 Mock 说成"真实写入 / 生产闭环 / 真实回读通过"？
5. 镜头 6 的 `details` 里，`proposal_status` 是否与真实路径一致（`applying` / `readback_pending`，不是硬编码）？
6. 镜头 7 是否**明确说出"这条路径没有收敛"**？
7. 是否一次连续录制、无剪辑拼接、无中途换窗口导致时间轴断裂？
8. Token / 姓名 / 学号 / 手机号是否全部打码或用虚拟数据？
