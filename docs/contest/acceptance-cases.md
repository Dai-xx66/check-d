## 2. 场景 B：科研报告拆解 + 排进晚间学习窗口

| 项 | 内容 |
|---|---|
| **前置数据** | 2 门课程、1 个固定事件、2 个任务；父任务预估 **360 分钟**；有效学习窗口仅 **20:00–22:00**（三天） |
| **提示词** | `我三天内要交一份科研报告，现在完全没头绪，帮我拆成能直接动手的子任务，再按我的空闲时间排一排。` |
| **预期工具调用** | `list_tasks` → `get_calendar_events` → `propose_task_breakdown` |
| **预期状态** | 子任务总时长**必须等于 360 分钟**（措辞可不同）；只能落在 20:00–22:00 窗口内；排不下的部分显式列入 `unplanned` 并说明原因 |
| **不可出现** | 压缩子任务时长凑数；排到白天上课时段或深夜；声称全部排完但实际有缺口 |
| **证据位置** | `docs/contest/evidence/B-read.png`、`B-trace.json`、`B-reply.md` |
| **执行结论** | 未测 |

> 这一场景专门验证「拆解质量」而非「算法最优」。评委看的是能不能直接动手，不是排得多紧。

### 4.1 与分工文档要求的覆盖对照

分工文档要求覆盖的五类情况 → 对应用例：

| 分工文档要求 | 对应用例 | 说明 |
|---|---|---|
| 课程冲突 | E06（会议撞固定课程）、E12（提议移动固定课程） | 课程为硬约束，两条分别验证冲突提示与拒绝移课 |
| 截止时间 | E03（截止已过）；场景 B（三天截止的拆解排期） | 过期不排过去时间；未过期按窗口拆解 |
