## 1. 五分钟演示（现场 / 录屏通用）

**总原则**：一次完整闭环，不切换多个场景。宁可只演示 A 场景走通，也不要把三个场景都演成半截。

| 时间 | 画面 | 讲解词（照读即可） | 成功标准 |
|---|---|---|---|
| 0:00–0:30 | Agent 对话窗空白 | 「这是 WorkBuddy 上的 CheckD 助手。它不接管你的日历，只在你说要改的时候，先给方案、等你点头。」 | 链接可打开、非本人账号可访问 |
| 0:30–1:20 | 输入场景 A 提示词 | 「我问它明天有什么课和事，顺便把英语复习塞进空档。」→ 展示工具调用日志 | 日志中依次出现 `list_tasks`、`get_calendar_events` |
| 1:20–2:30 | 提案卡片 | 「它没有直接写。这里列了 3 个块，每个都写明依据：第 2 个块是因为 14:00 有课才挪到 16:00。」 | 每个块带 `reason` 字段 |
| 2:30–3:20 | 点「批准并写入」 | 「点确认，它才写；写完立刻回读，把结果再拿给你看。」 | 回读结果与提案一致 |
| 3:20–4:10 | 计划前/后对比 | 「左边是原来的安排，右边是现在的。只动了 1 项，其余没碰——这是我们的约束：固定课程永不移。」 | 移动条数 ≤ 2，课程 0 变动 |
| 4:10–4:40 | 故意触发一次失败 | 「如果我不批准，它什么都不会改。」（或触发 E11 工具超时，展示「未确认成功」提示） | 有明确失败提示，无写入 |
| 4:40–5:00 | 收尾 | 「它做三件事：读懂、提案、等你批准后执行并核验。就这些。」 | — |

**录屏要求**：连续录制，不剪辑拼接；画面包含浏览器地址栏（证明是真实链接）；不出现任何真实姓名、`C:\Users\<姓名>\` 路径。

## 2. 五分钟答辩（评委问什么，怎么答）

按评委最可能问的顺序排，每条给「一句话答案 + 支撑证据」。

| # | 预判问题 | 一句话答案 | 证据 |
|---|---|---|---|
| 1 | 这和直接用 ChatGPT 排日程有什么区别？ | 区别在**它不能自己改你的数据**：所有改动必须经你批准，且批准后回读核验才算成功。 | 演示 3:20 段落 + `agent-api-v1` 契约 |
| 2 | 凭什么说解决了真问题？ | 依据是 5 份同学访谈：3 人提到「排了不做、做了没记」，2 人提到临时会议后计划全废。 | `docs/submission/needs-evidence-pack.md` |
| 3 | 固定课程被挪了怎么办？ | 硬约束写进契约：课程不可移，模型提议移课时直接拒绝并给替代方案。 | 边界用例 E06、E12 |
| 4 | 网断了 / 工具超时呢？ | 明确报「未确认成功」，不假装成功，也不编造明天的安排。 | 边界用例 E11 |
| 5 | 重复点确认会不会排两套？ | 幂等：同一提案重复批准只生效一次，第二次返回「已应用」。 | 边界用例 E08 |
| 6 | 数据安全怎么保证？ | 演示全用构造数据；真实数据脱敏；不收集账号密码。 | `docs/submission/privacy-checklist.md` |
| 7 | 用了哪些开源 / 平台能力？ | 表格已备：平台 WorkBuddy，客户端 Flutter/Drift/Riverpod，调度思路参考 Horolog（MIT，未复制代码）。 | `docs/contest/oss-disclosure.md` |
| 8 | 为什么不做全自动？ | 日程是高代价决策，误排一次用户就不信了；我们选择「提议 + 批准」换可信度。 | 产品取舍，可展开 30 秒 |

**答辩纪律**：不会的就答「这块目前没做，是下一步」；不要临场编功能。

## 3. 彩排检查单（11/07）

- [ ] 用**非本人账号**（另一台设备、另一网络）打开链接，确认可访问
- [ ] 三组场景各连续跑通 3 次（对应总计划「各连续通过三次」）
- [ ] 计时：演示控制在 4:40–5:10；超时先砍 4:10 的失败演示段
- [ ] 录屏文件命名 `checkd-demo-v1-<日期>.mp4`，放 `docs/contest/evidence/`
- [ ] 全程无真实姓名、学号、教师名、`C:\Users\` 路径、密钥
- [ ] 投影分辨率下字号可读（提案卡片文字 ≥ 16pt 等效）

## 4. 降级方案（真实链路不可用时）

> **边界声明**：本节只是现场故障的应急话术，**不是架构降级方案**。演示主体必须是 WorkBuddy 可访问的真实 Agent；「ADP 主建 + 过程材料」等替代路径未经组委会书面确认前不得出现在演示中（2026-10-30 全队通知口径）。

| 故障 | 降级做法 | 严禁做法 |
|---|---|---|
| Agent 链接打不开 | 改为本地录屏回放（提前录好的连续视频），并当场说明「这是 X 月 X 日录制的真实运行」 | 假装现场在跑 |
| 只读工具超时 | 演示 E11 失败路径本身，把它讲成设计亮点 | 用 Mock 数据冒充真实返回 |
| 写入失败 | 展示错误提示 + 回读不一致的检测过程 | 展示「已保存」但数据库没变 |
| 网络完全不通 | 展示 trace 日志与前一日的成功录屏 | 临时改口说「不需要联网」 |
