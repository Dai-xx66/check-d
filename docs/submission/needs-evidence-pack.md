# 需求依据采集包（为「需求价值 30 分」取证）

> 主笔：M3（同学 C）· 2026-10-29
> **为什么必须做**：方案原件第八节评分表，「需求价值」占 **30 分**，全表最高；且第七节明确写「教育智能体专项赛道：重点考察教育场景的真实性与教学价值，**须提供课程、科研或校园业务依据**，说明对学生学习或教师工作的实际改善」。

我们现在三组场景全部是我构造的 fixture（`fixtures/education/`）。**构造数据能证明"这东西能跑"，不能证明"这东西该做"。** 这 30 分里，至少 10–12 分取决于能否拿出真实依据。

好消息：这件事不需要队友配合，也不需要等 Agent 上线，**一个人两小时内能做完**。

## 二、访谈问卷（可直接复制发微信）

> 用法：找 5 个不同专业/年级的同学，微信语音或当面，5 分钟内问完。**不要引导答案**，先问"你现在怎么做的"，再问"哪里难受"。
> 关键：至少 2 人要能说出**具体的一次失败经历**（哪天、什么事、结果怎样）。这一段原话最有价值。

```
我在做一个课程项目，想了解大家平时怎么安排学习和任务，就 5 个问题，几分钟：

1. 你现在用什么管课程和作业？（纸质/手机备忘录/日历App/待办App/什么都不用）
   如果有两个以上，它们之间会同步吗？

2. 上一次"计划被临时事情打乱"是什么时候？当时怎么处理的？
   （能不能说具体点：哪天、什么事、最后有没有漏掉什么）

3. 重新安排一次大概要花多久？（几分钟 / 半小时 / 干脆不排了）

4. 有没有出现过"以为排好了，结果忘了某件事"？最近一次是什么？

5. 如果有个工具能读你的课表，自动把作业拆成小块排进空档，
   排不下的时候明确告诉你"这周有 3 小时排不进去"，你会用吗？
   最担心什么？（隐私 / 不准 / 懒得录数据 / 其他）
```

**记录要点（只记这四项，别记多了）：**
- 现在用什么工具（→ 证明"多工具割裂"这个痛点成立）
- 一次具体的失败经历原话（→ 大纲里最有力的引用）
- 重排耗时数字（→ 量化基线的分母）
- 最担心什么（→ 直接写进"已知局限"，原件要求"说明适用范围、已知局限"）

## 四、真实课表脱敏模板

**采集**：截一张自己（或愿意提供的同学）本学期课表，或从教务系统导出。

**脱敏规则（必须做，否则违反原件"不得使用未脱敏个人信息"）：**

| 原始字段 | 处理方式 | 示例 |
|---|---|---|
| 课程名称 | 保留通用课名，删掉本校特有课号 | `高等数学A(2024级)` → `高等数学` |
| 教师姓名 | 改为「X老师」 | `张伟` → `张老师` |
| 教室 | 改为「教学楼X-房间号」 | `B6-705` → `教学楼A-301` |
| 班级/学号 | **全部删除** | —— |
| 周次 | 保留（排程算法需要） | 1-16 周 |
| 学分/学时 | 保留 | 4 学分 |

**入库格式**（与现有 fixture 字段对齐，可直接被 `validate_fixtures.py` 校验）：

```json
{
  "meta": {
    "scenario_id": "scenario_d_real_timetable",
    "source": "真实课表（已脱敏）· 采集于 2026-10-__",
    "privacy": "课程名已通用化，教师与教室已替换为占位符，无学号/姓名"
  },
  "fixed_events": [
    { "id": "ev_r01", "title": "高等数学", "weekday": 1,
      "start_minute": 480, "end_minute": 570, "location": "教学楼A-301" }
  ]
}
```

> 脱敏完跑一次：`python fixtures/education/validate_fixtures.py --privacy`，必须 0 失败才能进仓库。

## 五、大纲里「需求来源」段落范文（改数字即可用）

> 直接粘进 `docs/submission/draft-outline.md` 的第 1 页。占位符用 `__` 标出。

```
【需求来源】
本作品源于对本校 __ 个专业 __ 名在校生的访谈（2026 年 10 月）。
受访者中 __ 人同时使用 2 种以上工具管理课程与任务，__ 人报告曾因临时
安排导致任务遗漏；重新安排一次计划的耗时中位数为 __ 分钟。
典型情形为：课程表固定在教务系统、作业记在备忘录、临时会议在微信群，
三者互不联通，一旦出现临时安排，原有计划整体失效且无人重新校核。
本作品以真实课表结构（已脱敏，__ 门课程 / __ 个固定时段）为输入基线，
目标是把上述重排耗时从 __ 分钟降至 __ 分钟以内，并消除"排不下却不说"的静默失败。
```

**这段的杀伤力在哪：** 它同时命中官方三个关键词——「聚焦真实痛点」（有访谈）、「实际应用价值」（有耗时对比）、「场景适配性」（有真实课表）。评委看大纲时，这一段是唯一能判断"是不是编的"的地方。

## 六、量化指标怎么算（别编数字）

| 指标 | 怎么得到 | 注意 |
|---|---|---|
| 重排耗时（前） | 访谈第 3 问的中位数 | 用中位数不用平均数，避免极端值 |
| 重排耗时（后） | Agent 跑通后**实测 3 次取中位数** | 必须真实跑，不许估 |
| 遗漏任务数（前） | 访谈第 4 问「有过」的人数 | 这是基线 |
| 遗漏任务数（后） | 用 E02/E07 边界用例验证「排不下必提示」 | 对应 `boundary_cases.json` |
| 计划稳定性 | 最小扰动指标：一次临时变更影响的条目数 | 场景三设计为「1 动 3 不动」 |

> ⚠️ 在 Agent 跑通之前，**「后」这一列必须留空**。先编好数字再补证据，一旦被现场抽题验出来，性质比没有数字严重得多（原件第九节：测试造假取消资格）。

## 八、如果访谈做不成（备选方案）

真找不到 5 个人，按这个顺序降级，**不要编造**：

1. **3 人 + 自己**（含本人真实经历），大纲写「访谈 3 名在校生及作者本人实践」
2. **公开依据**：引用学校教务处公开的校历、培养方案结构（这些是可核查的公开信息），说明"课程时段固定、临时调课存在"这一客观事实
3. **明确标注**：「本阶段需求依据来自 X 人访谈与公开校历，后续将扩大到 Y 人」——诚实标注局限，原件本来就要求「说明已知局限」

> 最差的做法是写「我们调研了 50 名同学」却没名单。评委不问则已，一问就崩，而且会连带怀疑后面所有数据。
