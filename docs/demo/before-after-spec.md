# 「计划前 / 计划后」差异展示规格 v1.0

> 归属：M3（同学 C）· 2026-10-29
> 对应可执行视觉稿：`docs/demo/before-after-preview.html`（浏览器直接打开，可点「批准并写入」看状态切换）
> 目的：让用户一眼看懂「Agent 打算改什么」，并在批准前能反悔。这是比赛闭环里「生成结果 → 核验反馈」的可视化载体。

---

## 1. 为什么需要这块

比赛硬性要求闭环是：**理解需求 → 检索依据 → 执行操作 → 生成结果 → 核验反馈**。
其中「生成结果」如果只输出一段文字（"我帮你把英语复习安排在 20:00"），评委无法确认 Agent 是否真的理解日历；
「核验反馈」如果只说"已完成"，也无法证明写入了。

所以展示层必须做到三件事：

1. **前后对照**：同一时间轴上，改前 / 改后并排，变化项高亮。
2. **逐条解释**：为什么排在这个位置、为什么不排另一个位置。
3. **状态可见**：待确认 / 已写入 / 已核验，三态不能混。

## 2. 布局（三段式）

```
┌────────────────────────────────────────────────────────┐
│ 标题：明天的安排 · 计划提案                             │
│ 副标题：学生A · 10月30日 周五 · 北京时间    [待你确认]  │
├────────────────────────────────────────────────────────┤
│ [新增 1] [移动 0] [保持不变 4] [未安排 0]   ← 四个统计   │
├───────────────────────┬────────────────────────────────┤
│ 计划前（只读快照）     │ 计划后（提案预览）              │
│ 08:00 ─                │ 08:00 ─                        │
│  …                     │  …                             │
│ 14:00 ▓ 数据结构       │ 14:00 ▓ 数据结构               │
│ 19:00 ▓ 学生会例会     │ 19:00 ▓ 学生会例会             │
│ 20:30 ▨ 高数习题       │ 20:00 ✚ 英语复习（新增虚线）   │
│                        │ 20:30 ▨ 高数习题               │
├────────────────────────────────────────────────────────┤
│ 变化说明（逐条，可核对）                                │
│ ＋ 新增：英语六级词汇复习 20:00-20:25 …                 │
│ ✓  未改动：数据结构、例会、高数习题 …                   │
│ i  选时依据：…                                          │
├────────────────────────────────────────────────────────┤
│ 批准前不会写入任何数据        [取消] [批准并写入]        │
└────────────────────────────────────────────────────────┘
```

## 3. 视觉规则（沿用项目「小羊日常四色轻玻璃风」）

| 元素 | 取值 | 说明 |
|---|---|---|
| 页面底色 | `#FFFBF7` | 暖白 |
| 卡片 | `#FFFEFC` + 1px `#F1E8E5` + `0 8px 24px rgba(180,150,150,.08)` | 轻玻璃/轻阴影 |
| 圆角 | 卡片 24px / 块 10px / 按钮 999px | 大圆角 |
| 课程块 | 底 `#E6F2FF` 边 `#CFE4FA` 字 `#3F6884` | 淡蓝 = 课程与时间安排 |
| 固定事项块 | 底 `#F0EBFF` 边 `#DED4F7` 字 `#5B4C8A` | 淡紫 = 不可移动 |
| 普通任务块 | 底 `#FFF8F5` 边 `#F1E8E5` 字 `#3F3435` | 中性 |
| 新增块 | 底 `#FFE7ED` 边 `1.5px dashed #F47F9E` 字 `#A8465F` + 「新增」角标 | 粉红 = 主操作与变化 |
| 已写入后 | 虚线变实线 | 状态区分 |
| 数字强调 | 新增 `#EA668A` / 移动 `#A58AE2` / 保持 `#7CBFA2` | 四个统计各一色 |

禁止：不要用红色表示删除、不要用绿色表示新增（与 A 股/国内习惯冲突且本项目语义是「绿=完成」）。

## 4. 数据契约（M1/M2 必须按此返回）

展示层只吃这一个结构，字段名以 M0 冻结的 `agent-api-v1.md` 为准；下面是 M3 的**最小需求**：

```jsonc
{
  "proposal_id": "p_20261029_001",
  "base_version": 17,                      // 必须：用于版本冲突检测（边界用例 E09）
  "target_date": "2026-10-30",
  "timezone": "Asia/Shanghai",
  "state": "PENDING_APPROVAL",             // DRAFT|VALIDATED|PENDING_APPROVAL|APPLIED|REJECTED|EXPIRED|FAILED
  "before": [                              // 只读快照
    { "ref": "course:course-ds", "title": "数据结构", "start": 840, "end": 940,
      "kind": "course", "hardness": "hard" }
  ],
  "changes": [
    { "op": "add",    "ref": "task:task-eng-vocab", "title": "英语六级词汇复习",
      "start": 1200, "end": 1225, "kind": "task", "hardness": "soft" },
    { "op": "move",   "ref": "task:task-calc-homework", "from": [900, 960], "to": [990, 1050] },
    { "op": "keep",   "ref": "task:task-ds-report" }
  ],
  "explanations": [
    { "ref": "task:task-eng-vocab", "reason": "例会结束后到高数习题之间有 30 分钟空档，可完整容纳 25 分钟" }
  ],
  "unplanned_tasks": [
    { "ref": "task:xxx", "minutes": 60, "reason": "未来两天无 ≥60 分钟连续空档" }
  ]
}
```

**字段级硬要求：**

- `start` / `end` 一律用**当天分钟数**（0-1440），不要传 "20:00" 字符串，避免时区与格式歧义。
- `op` 只能是 `add` / `move` / `remove` / `keep` / `update`，展示层按此上色。
- `unplanned_tasks` 为空数组时必须显式给 `[]`，不能省略字段（否则前端无法区分"没有未安排"和"没算"）。
- 没有 `explanations` 的 `change` 视为不合格：每个 `add`/`move` 至少一条理由。

## 5. 状态机与文案

| 状态 | 顶部 chip | 主按钮 | 辅助文案 |
|---|---|---|---|
| `PENDING_APPROVAL` | 「待你确认」橙色 `#9A6B3A` | 批准并写入 | 批准前不会写入任何数据 |
| 写入中 | 「正在写入」 | 禁用 + loading | — |
| `APPLIED` | 「已写入 · 已回读核验」绿色 `#3F7A61` | 禁用 | 已写入 N 条变更，回读结果与提案一致 |
| `REJECTED` | 「已取消」灰 | 批准并写入（可重来） | 未写入任何数据 |
| `EXPIRED` | 「提案已过期」 | 重新生成 | 日历已被修改，请重新生成提案 |
| `FAILED` | 「写入失败」 | 重试 | 附具体原因，如「版本冲突」 |

**绝对不能出现：** 写入失败却显示「已完成」；工具超时却显示旧数据当新结果（对应边界用例 E11）。

## 6. 交互细节

1. **差异必须可聚焦**：鼠标悬停某个 `change` 行，左右两侧对应时间块同时加 2px 外发光，帮助定位。
2. **跨日块**：`end > 1440` 时拆成当天 `start-1440` 与次日 `0-(end-1440)` 两段，且次日段标注「次日」。
3. **空状态**：`changes` 为空 → 显示「今天没有需要调整的地方」，而不是空白面板。
4. **未安排提示**：`unplanned_tasks` 非空时，在变化说明区顶部插入橙色提示条，写明总量与原因（对应 E02/E07）。
5. **不隐藏冲突**：任何硬冲突不自动吞掉，显示为红色描边块 + 「与课程冲突」标签，让用户决策（对应 E06）。

## 7. 与 WorkBuddy 的落地方式（给 A 的说明）

WorkBuddy 内如果无法渲染自定义 HTML，退化方案按优先级：

1. **Markdown 表格 + 时间轴文本版**（最低可用）：

```
计划前                 计划后
14:00 数据结构         14:00 数据结构
19:00 学生会例会       19:00 学生会例会
20:30 高数习题         20:00 英语复习（新增 25 分钟）
                       20:30 高数习题（不变）
```

2. 平台支持富文本卡片时，用上面第 3 节的色板做卡片渲染。
3. 无论哪种形态，**四个统计数字 + 逐条理由 + 明确的状态标签**三样都不能省，这是评委判断"是否真跑通"的依据。
